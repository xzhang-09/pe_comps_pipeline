# PE Comps Pipeline

## Project Overview

This tool helps private equity analysts automatically build a set of comparable
public companies to benchmark a private target company for valuation purposes.
Given a target's industry, financial profile, and business description, it
fetches a universe of public peers, extracts structured business-model
attributes with an LLM, trains an XGBoost model to predict EV/EBITDA from
fundamentals, and produces a ranked Top 15 comps report with valuation
multiples, financial benchmarks, and a predicted valuation range.

The technical approach: candidate tickers are discovered dynamically from
SEC EDGAR by SIC code (no hardcoded ticker list) — a "primary" bucket of
SIC codes expected to actually resemble the target, and an "adjacent" bucket
of broader, related SIC codes included purely to add training-data volume;
financials (revenue, EBITDA, gross profit, capex, net debt) and business
descriptions are pulled from SEC EDGAR's XBRL filings via `edgartools`; market
capitalization and sector classification come from the Financial Modeling
Prep (FMP) API; OpenAI extracts structured business-model fields from each
company's description and judges its own extraction quality; and an
XGBoost regressor, explained with SHAP, predicts EV/EBITDA multiples from
financial + business-model features. Companies whose actual multiple is
best explained by fundamentals (smallest residual) are ranked as the most
reliable comps.

## Quick Start

```bash
git clone <repo-url>
cd pe_comps_pipeline
pip install -r requirements.txt

# macOS only: xgboost needs the OpenMP runtime
brew install libomp

# API keys — put these in a .env file in the project root (gitignored),
# never commit them or paste them into chat/code:
#   OPENAI_API_KEY=sk-...
#   FMP_API_KEY=...
# python-dotenv loads .env automatically; no manual `export` needed.

# Edit config.yaml with your target company details, then run:
python -m src.pipeline

# Force model retraining:
python -m src.pipeline --force-retrain

# Run tests:
pytest tests/ -v
```

## Configuration Guide

All settings live in `config.yaml`:

- **`target_company`** — the private company you're valuing.
  - `name`, `description`: used in the report and sent to the LLM extractor.
  - `gics_sector` / `gics_industry`: GICS codes, for reference only (not used
    by any pipeline logic — `sub_sector_description` from the LLM is what
    downstream comp selection actually uses).
  - `revenue_usd_mm`, `ebitda_margin_estimate`: your estimates for the target;
    feed directly into the XGBoost prediction. Any other financial feature
    the model needs (gross margin, revenue growth, net debt/EBITDA) falls
    back to the training set's median since the target doesn't have public
    filings to pull them from.
  - `geography`: descriptive only.
  - `primary_sic_codes` / `adjacent_sic_codes`: SIC codes used to discover
    candidates from SEC EDGAR (`src/sic_universe_builder.py`). `primary`
    should be the SIC codes most directly matching the target's actual
    business — these are the ones expected to actually surface as comps.
    `adjacent` is a broader, related set included only to add training-data
    volume/diversity for the XGBoost model; candidates from it are not
    expected to be selected as comps themselves.
- **`universe`**
  - `max_candidates`: upper bound on the total candidate pool, after market-
    cap filtering via FMP.
  - `primary_allocation_pct`: what fraction of `max_candidates` is reserved
    for the primary bucket vs. the adjacent bucket (e.g. `0.5` splits it
    evenly). If a bucket's actual candidate count is below its quota, the
    unused quota is simply not filled — it's not redistributed to the other
    bucket.
  - `min_revenue_usd_mm` / `max_revenue_usd_mm` / `min_ebitda_margin`: defined
    for future filtering use; not currently enforced in code.
- **`llm`**
  - `extraction_model` / `judge_model`: OpenAI models for business-model
    extraction and judging (e.g. `gpt-4.1` / `gpt-4.1-mini`).
  - `temperature`, `max_tokens`: passed to every OpenAI call.
  - `batch_size`: how many companies to process between checkpoint saves.
  - `judge_threshold`: judge scores below this set `low_confidence_flag=True`,
    which hard-excludes the company from the final Top 15 (see Reporter logic).
- **`output`**
  - `top_n_comps`: intended Top-N size for the report (currently fixed at 15
    in `src/reporter.py`).
  - `report_formats`: which report formats to produce (CSV and HTML are
    always both generated by `reporter.generate()` regardless of this list).

## Understanding the Output

`python -m src.pipeline` produces `outputs/comps_report.csv` and
`outputs/comps_report.html`. The HTML report has 6 sections:

1. **Target Company Summary** — name, description, predicted EV/EBITDA range,
   number of comps analyzed, run timestamp.
2. **Valuation Multiple Distribution** — P25/median/P75/mean for EV/EBITDA and
   EV/Revenue across the Top 15 comps only.
3. **Financial Benchmarks** — for EBITDA margin, revenue growth, gross margin,
   and net debt/EBITDA: the Top 15's distribution plus where the target's
   estimate falls (percentile).
4. **Top 15 Comparable Companies** — ranked by how well each company's actual
   multiple is explained by its fundamentals (smallest residual first).
   Companies with `judge_score < 3` are flagged "(low confidence)".
5. **Model Diagnostics** — cross-validation error, training set size, top 5
   SHAP features, and (if `eval/results.md` exists) the pipeline's measured
   Precision@15 against real SEC proxy peer groups.
6. **Data Notes** — how many companies were excluded for low LLM confidence,
   how many tickers failed to fetch, and a standard disclaimer.

The CSV has one row per Top-15 comp with the same financial/business-model
fields shown in the report, for further analysis in Excel or elsewhere.

## Architecture

```
config.yaml -> [1] Universe Builder -> [2] Fetcher -> [3] LLM Analyzer
                                                              |
                                  [6] Reporter <- [5] Scorer <- [4] Feature Builder
```

1. **Universe Builder** (`src/universe_builder.py`) — discovers candidate
   tickers by SIC code via SEC EDGAR (`src/sic_universe_builder.py`), split
   into primary/adjacent buckets per `primary_allocation_pct`, then filtered
   by market cap via FMP.
2. **Fetcher** (`src/fetcher.py`) — financials + business description from
   SEC EDGAR (via `edgartools`), market cap/sector from FMP. Caches every
   company to `data/cache/{ticker}.json`.
3. **LLM Analyzer** (`src/llm_analyzer.py`) — OpenAI extracts business-model
   fields per company, then judges its own extraction. Checkpoints to
   `data/checkpoints/llm_checkpoint.json` for resumable runs.
4. **Feature Builder** (`src/feature_builder.py`) — merges financials + LLM
   features into a numeric matrix, with the target's `ev_ebitda` as the
   regression label.
5. **Scorer** (`src/scorer.py`) — trains XGBoost, runs 5-fold CV, computes
   SHAP feature importance, and predicts a range for the target.
6. **Reporter** (`src/reporter.py`) — selects the Top 15 comps and renders
   the CSV/HTML report.

## Evaluation Results

From `eval/results.md` (see that file for the full write-up). **Note:** these
numbers were measured against the earlier GICS-sector-based universe
(Industrials/Healthcare Equipment/Technology Hardware), before the pivot to
SIC-code-based discovery described above — they haven't been re-measured
against the current universe definition yet.

- **Precision@15 vs SEC proxy peer groups**: Mean 14.6% (raw), but most of
  the gap is universe-coverage, not ranking quality — restricting ground
  truth to peers that are actually reachable in that universe lifts this to
  ~30%. 10 of 15 test companies had an extractable peer group.
- **LLM extraction consistency** (30-company re-extraction sample):
  business_model 100%, revenue_recurrence 100%, customer_type 96.7%,
  capital_intensity 96.7%, primary_value_driver 100%.
- **Manual review**: see `eval/manual_review_sample.txt` and the "Manual
  Review Results" section of `eval/results.md` for accuracy rates from
  hand-checking 15 companies (filled in by the developer, not automated).

## Known Limitations

- **Data coverage**: public companies only, limited to whatever SEC EDGAR has
  filed 10-Ks under the configured `primary_sic_codes`/`adjacent_sic_codes` —
  not the full market. The data layer could be extended with Capital IQ or
  PitchBook for private-company coverage and a larger universe.
- **Financial data quality**: a large fraction of companies are missing a
  valid `ev_ebitda` label even after fetching (FMP free-tier coverage gaps,
  XBRL tagging gaps, outlier filtering) — in one measured run, 151 SIC-based
  candidates yielded only 83 with a usable label (~45% missing). Outliers
  (e.g. EV/EBITDA > 100x or negative) are automatically set to `None` rather
  than included; many of these come from genuinely thin/negative-EBITDA
  companies in the adjacent bucket, for which EV/EBITDA isn't a meaningful
  multiple in the first place.
- **Model scale & comp heterogeneity**: the XGBoost model trains on well
  under 100 companies in a typical run — predictions are directional
  estimates, not precise valuations, and the cross-validation error band
  reflects that. Mixing a heterogeneous adjacent bucket (e.g. low-multiple
  industrials alongside high-multiple instrumentation/robotics names) into
  the training set can widen the predicted range without necessarily adding
  useful signal; tightening the adjacent SIC codes is a more direct fix than
  adding more training rows.
- **LLM extraction**: quality depends on the underlying business description.
  Companies with short, generic, or boilerplate-heavy EDGAR descriptions
  produce less reliable extractions; the judge step exists specifically to
  flag and exclude those (`low_confidence_flag`).
- **Evaluation**: Precision@15 of ~30% (universe-adjusted) means roughly a
  third of the pipeline's selections match a company's own disclosed
  compensation peer group — a different, HR-driven selection criterion than
  ours (residual fit), so this is a directional sanity check, not a target
  to maximize. The remaining selections may still be useful comps but aren't
  validated by this particular ground truth.
- **No yfinance**: an earlier version of this pipeline used yfinance for
  market data, but it proved unreliably rate-limited in practice. It was
  replaced entirely with FMP (market cap, sector) + SEC EDGAR (everything
  financial). FMP's free tier itself has a daily request quota — large
  batch runs may need to be split across days or run with a paid plan.

## Cost Estimate

- SEC EDGAR: free.
- FMP free tier: free, but capped at a daily request quota (paid plans lift
  this if you need to run the full universe repeatedly in one day).
- OpenAI API for ~150 companies (extraction + judge + target): well under
  $1 at current `gpt-4.1` / `gpt-4.1-mini` pricing — measured at roughly
  $0.40-0.80 per full run during development.
- Cached runs (model already trained, LLM checkpoint exists, FMP/EDGAR data
  cached): effectively free — only the target's own LLM extraction and
  prediction re-run.
